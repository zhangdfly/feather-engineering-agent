# Hook 契约

## v1 决策

不实现 Hook。

当前规则是静态工程约束，没有会话档位、开关状态或工具拦截需求。Agent Skill 提供可移植的按需行为。

现在加入 Hook 会产生：

- 不同宿主的事件与输出格式；
- 额外运行时依赖；
- 重复注入造成的 token 成本；
- 父 Agent 与子 Agent 的规则重复；
- 规则正文与运行时副本漂移。

## 何时重新评估

只有出现可复现证据时才加入 Hook：

1. 插件安装后 Skill 经常没有自动触发；
2. 子 Agent 无法继承项目指令并稳定违反核心规则；
3. 需要会话内启用、停用或强度档位；
4. 需要在工具执行前做确定性阻断，而不只是影响生成结果。

## v2 最小契约

如果满足上述条件：

- 优先只使用 SessionStart；
- 注入同一份 Skill 规则，不维护 Hook 专用规则副本；
- 禁止每个用户消息重复注入全文；
- 每个宿主拥有自己的薄适配器，不建立包含宿主判断的共享运行时；
- Hook 不得修改 Skill 规则或项目代码；
- 必须用评测证明 Hook 相比 Skill/instructions 有实际收益。

仓库故意不创建 `hooks/` 目录，避免宿主自动发现尚未启用的配置。
