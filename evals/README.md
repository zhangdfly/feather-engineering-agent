# 回归案例

`evals/` 记录规则需要防止的真实失败模式。它不会在正常编写或 PR Review 时加载，也不会直接改变 Agent 行为。

评审结束后，如果用户反馈可以跨项目复用：

1. 更新拥有该职责的现有规则；
2. 在 `docs/` 或 `code/` 添加最小回归案例；
3. 在同一个变更中提交规则与案例。

每个案例包含：

- `模式`：编写模式或 PR Review 模式；
- `输入`：最小提示、代码或 diff；
- `合格结果`：期望实现或期望 Review comment；
- `失败特征`：需要防止的遗漏、误报或错误结构。

PR Review 产生的案例还应包含 `反馈依据`，用一句匿名化描述说明用户指出了什么遗漏或误报。

案例应匿名化，只保留触发规则所需的结构。
