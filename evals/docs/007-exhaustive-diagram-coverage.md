# 用例：要求全量图示时逐项核对模块、文件和方法

## 模式

编写模式

## 输入

读者明确要求模块图覆盖所有模块，时序图覆盖所有运行时文件、公开方法和跨模块复用的方法；可以按流程拆成多张图。当前代码有五个模块：

| 模块 | 运行时文件与目标方法 |
|---|---|
| `ingest` | `Watcher.ts`: `start()`、`onRecord()`、`stop()`、公开的 `status()` |
| `parse` | `Parser.ts`: `parse()` |
| `shared` | `normalize.ts`: 导出的 `normalize()`，被多个模块复用 |
| `store` | `Writer.ts`: `write()`、`close()` |
| `metrics` | `Reporter.ts`: `report()` |

真实流程：`start()` 建立采集；记录到达后依次执行 `onRecord()`、`normalize()`、`parse()`、`write()`、`report()`；停止时 `stop()` 调用 `close()`。`status()` 是公开接口，但当前没有调用方。`schema.d.ts`、`theme.css`、静态配置和 `Writer.test.ts` 没有产品运行时交互。

## 合格结果

- 一张或多张模块图能找到五个模块及真实交接，不能因 `metrics` 不在最初的主路径上就略去；
- 分流程的时序图合集包含五个运行时文件，并在箭头上逐一标明九个目标方法；八个已有调用写明真实调用方，`status()` 另画标明“未接入”的契约时序图，不能捏造调用方；模块或路径能辨明各列归属；
- 对照源码清单建立简短的文件/方法到图的对应关系，确认没有遗漏；纯声明、样式、静态配置与测试由模块图或文件职责索引覆盖；
- 未接入的公开接口也出现在契约时序图中，但与实际运行路径明确区分。

## 失败特征

- 仅用主流程图代替全量覆盖，漏掉 `metrics` 模块、`Reporter.ts` 或 `report()`；
- 参与者出现 `Watcher.ts` 却未标出 `stop()`，或只列出方法名但没有实际调用/回调；
- 因为 `status()` 尚无调用就不在任何时序图中覆盖，或编造一个现有的调用方；
- 将测试、样式硬塞进时序图，或者把具有执行逻辑的配置文件误当成纯静态配置排除；
- 凭印象声称“全部覆盖”，未核对模块、文件和公开/复用方法的清单。

## 边界条件

只有读者明确要求全覆盖时才以逐项对应为验收标准；简单项目或未要求全量图示的任务，仍只画有助于理解关系和顺序的图。多个方法可以出现在同一张图，不为每个方法复制一张图。

## 反馈依据

读者明确要求模块图覆盖所有模块；时序图集合覆盖运行时文件与公开及共享方法，并允许纯声明、样式、静态配置和测试改用模块图或文件职责索引说明。
