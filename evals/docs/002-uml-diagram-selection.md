# 用例：复杂技术文档的图表选择

## 模式

编写模式

## 输入

为插件仓库编写架构文档，同时说明：

- Skill 目录的文件层级；
- plugin manifest、`SKILL.md` 和领域规则之间的依赖；
- Agent 收到文档任务后加载入口 Skill 和文档规则的核心顺序。

## 合格结果

- 文件层级保留为易读的 `text` 目录树；
- 组件依赖使用 GitHub 可渲染的 Mermaid `flowchart`，必要的模式边界使用 `subgraph`；
- 多参与者的核心调用顺序使用 Mermaid `sequenceDiagram`；
- 图中的名称和方向与正文一致，正文不逐项复述图。

## 失败特征

- 把文件目录树机械转换成组件图；
- 继续用 ASCII 字符图、截图或纯文字描述组件依赖；
- 用组件图代替具有明确参与者和调用顺序的核心逻辑；
- 使用 GitHub 无法渲染的 Mermaid 语法。

## 反馈依据

用户明确指出文件结构使用文本树更清楚，而依赖方向应改为可渲染的 Mermaid 图。
