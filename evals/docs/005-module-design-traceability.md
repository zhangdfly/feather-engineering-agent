# 用例：模块设计的覆盖与阅读路径

## 模式

编写模式

## 输入

一个仓库已有客户端、服务端和共享协议。读者要求从 README 看懂模块关系，再到模块设计和主要源码，特别是一个可选外部事件如何触发客户端动作并到达服务端。

已有整体设计只画了三者的关系；本地设计各有五行，主要是文件名。代码中事件桥拥有独立连接和重连，页面编排负责触发动作与提示采集失败，服务端会话负责接收控制消息并切换状态。能力清单与验证计划另有文档维护。

## 合格结果

- 先核对真实调用链；整体设计交代跨模块关系，本地设计分别说明事件来源、状态所有权、调用交接、失败与重连边界，并链接主要文件或类型；
- 从已有阅读入口能到达关系说明、相关模块设计及源码，必要时增加承载新信息的模块导航，不建立只作转发的多层文档；
- 不用文件索引或一张总图假充全部设计，也不重复已有能力清单和验证计划；
- 按模块实际复杂度写细节，不因文件多就拉长每篇或给每个简单目录新建文档。

## 失败特征

- 将过短的本地设计保留为文件列表，遗漏事件桥、页面和服务端各自的状态、错误与交接；
- 只延长整体设计，却无法从 README 找到负责关键行为的模块和源码；
- 为显得全面而在每个层级重复整份能力清单，或按文件数机械要求相同篇幅。

## 边界条件

规模小、流程简单且文档可连续阅读时，单份设计和直接源码链接即可；用户未要求逐层导航时不强制添加目录页。

## 反馈依据

读者多次指出：缺少能覆盖真实代码的设计，增加的文件索引和简短模块页仍无法解释流程；后来要求从项目入口逐层找到模块关系、局部设计与实现。
