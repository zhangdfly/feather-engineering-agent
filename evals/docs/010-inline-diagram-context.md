# 用例：核心说明直接放入图中

## 模式

编写模式

## 输入

为领域模型中的核心对象补充中文说明。现有 Mermaid `classDiagram` 只显示 `CourtTask`、`Memorial` 和 `AttentionItem`，图下另有一张表逐项给出中文名称和一句话职责。读者反馈不希望在图和表之间来回比对。

## 合格结果

- 保留与代码或协议对应的英文对象标识；
- 在对应类标签中直接补充中文名称和一句话职责，使读者只看图即可理解当前关系；
- 删除只重复这些对应关系的图外表格；
- revision、失败语义等不适合放进类框的长约束仍由正文单点定义；
- 对象过多导致图拥挤时按职责拆图，不缩小文字或把段落塞进节点。

## 失败特征

- 图仍只有英文标识，要求读者到图外表格逐项查找名称和职责；
- 图中只保留中文名称，失去与代码、Schema 或协议对象的可追溯关系；
- 把完整字段解释、生命周期和异常语义全部塞进类框，使图无法扫读；
- 图内和表格重复同一组说明，继续产生两个需要同步维护的副本。

## 边界条件

复杂不变量、错误处理、字段定义或跨对象比较表具有独立信息时可以留在正文；规则只要求把理解当前图所必需且能保持简短的一一对应说明就地放入图中。

## 反馈依据

读者要求核心对象说明尽量直接写在图里，避免为了理解关系来回比对图和说明表。
