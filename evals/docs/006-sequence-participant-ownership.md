# 用例：时序图参与者的模块归属

## 模式

编写模式

## 输入

已有一张跨客户端、服务端和外部事件源的时序图，参与者只写 `Client`、`App`、`Session` 和 `Service`。读者无法判断事件由哪个模块接收、哪一列属于外部服务，也不知道失败或重连在哪个模块说明。实际调用链是客户端事件桥接收事件，页面编排调用同属客户端传输模块的网关连接器，再由连接器经 WebSocket 向服务端会话发送控制消息。

## 合格结果

- 为容易混淆的列标明负责模块或路径，明确外部参与者，箭头方向与实际交接一致；
- 在事件桥所属设计中解释触发、错误与重连，在会话所属设计中解释状态变化；图或相邻链接能让读者定位这些事实；
- 只有明确的参与者才省略路径，不因图已存在就省略用户要求理解的关键流程。

## 失败特征

- 仍只写通用角色名，要求读者从多份正文猜出每一列的位置；
- 加了模块名却把外部源画成内部模块，或让图中的调用绕过真实拥有交接的组件；
- 时序图只有成功路径，重要的触发或断线处理在所属模块的文档中也找不到。

## 边界条件

同一模块内且当前文档能唯一确定归属时，不强制每列重复完整路径；无需把所有错误细节挤进时序图。

## 反馈依据

读者指出多列时序图难以辨认参与者属于哪个模块；另一条可选事件流程虽然已有模块文档，关键的触发、交接和失败边界仍未得到解释。
