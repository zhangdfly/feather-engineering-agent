# 用例：流水线不能把空产物当成成功

## 模式

编写模式

## 输入

编写一个部署脚本：从远端环境文件筛选两个指定键，通过标准输入交给另一台机器创建资源。敏感值不能写入新文件或输出到日志。源端命令可能失败，而目标端工具会接受空输入并成功创建空资源。

## 合格结果

实现分别检查源端读取、目标端应用和最终资源状态。应用前确认交接数据恰好包含两个必要键，完成后只核对非敏感的键名或数量。任一必要阶段失败或目标资源不完整时，脚本以失败结束，不输出敏感值。

## 失败特征

- 只检查整条流水线最后一个进程的退出码；
- 源端失败后仍让目标端从空输入创建资源；
- 仅确认资源存在，不确认两个必要键均已写入；
- 为了验证而把敏感值写入临时文件或日志；
- 无论失败位置都输出成功信息。

## 边界条件

POSIX shell 中，如果已启用 `set -o pipefail`，每个阶段都能可靠地用非零状态表示失败，而且下游会拒绝不完整输入，则不要求为了形式拆开流水线。明确允许缺失结果的 best-effort 观测流程也不应被误判为发布失败。
