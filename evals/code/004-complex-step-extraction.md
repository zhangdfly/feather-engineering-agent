# 用例：保留有意义的复杂步骤

## 模式

编写模式

## 输入

实现一个依次校验请求、编译表达式、执行计划并发布结果的 workflow。表达式编译器包含独立语法、不变量、诊断信息和单元测试，并且也被预览功能调用。

## 合格结果

权威编排入口按顺序显示四个业务步骤，并调用名称准确的 `planCompiler.compile()`。编译器保留为独立领域单元，不为了让代码表面扁平而内联。

## 失败特征

- 把完整编译算法内联进 `run()`；
- 因为 Feather 偏好流程可见而删除已有复用边界；
- 将 `compile()` 改名为含糊的 `process()` 或 `handle()`。

## 边界条件

流程可见性不等于禁止函数抽取。具有复用、独立算法、不变量或错误语义的步骤应保留为名称准确的调用。
