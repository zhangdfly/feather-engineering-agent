# 用例：模块说明与流程注释

## 模式

编写模式

## 输入

一个新模块包含：

- 多个 GitHub Actions workflow；
- 一个通用文件名 `main.yaml`，内部包含权限与网络边界；
- 若干引导脚本，每个脚本按 step 1-N 改变系统状态；
- 一个名为 `process()` 的复杂函数；
- 一个名为 `sortById()` 且只按 `id` 排序的简单函数；
- 一个不支持注释的 JSON lockfile。

请补齐命名、模块说明和必要注释。

## 合格结果

- 模块 README 说明模块职责、执行顺序和每个直接文件用途；
- `main.yaml` 在文件开头说明职责，复杂权限与网络块解释边界和原因；
- workflow 的每个 step 说明业务目的，而不是复述 Action 或命令名称；
- 引导脚本的阶段注释说明状态变化和顺序依赖；
- `process()` 先改成准确领域名称，复杂逻辑再补不变量或失败边界；
- JSON lockfile 由模块 README 说明；
- `sortById()` 不添加“按 ID 排序”之类的冗余注释。

## 失败特征

- 只有模块顶层一条总注释，内部 workflow 和复杂配置块无说明；
- 每个 step 只有工具调用，读者无法看出权限获取和失败边界；
- 用注释解释 `process()`，却保留含糊名称；
- 为 `sortById()` 逐行添加与代码等价的注释；
- 因 JSON 不支持注释而完全不说明 lockfile；
- 为每个语法行写翻译性注释，掩盖真正需要解释的领域约束。

## 边界条件

标准文件名、简单转换和直接排序可以依靠目录上下文、模块 README 与准确名称自解释；不要求机械地重复语法。

## 反馈依据

用户指出仅有少量文件头注释不足以理解实现，要求每个子模块说明文件职责，并为 workflow 每个 step 与复杂代码、配置块补充目的和边界；同时明确简单自解释实现不应添加冗余注释。
